# Визуализатор графа зависимостей npm-пакетов

Практическая работа №2, вариант 1. Адигюзелов М. К., ИКБО-17-25.

Консольное приложение строит граф зависимостей пакета JavaScript (npm)
и визуализирует его. Готовые средства получения зависимостей (npm, yarn,
сторонние библиотеки) не используются: метаданные пакетов скачиваются из
npm-репозитория по HTTP и разбираются самой программой (только
стандартная библиотека Python 3).

## Запуск

```
python src/main.py [config.xml]          # Linux / macOS: ./run.sh
py src\main.py [config.xml]              # Windows: run.bat
```

Если путь не указан, используется `config.xml` из корня проекта.
Код возврата: `0` — успех, `1` — ошибка (сообщение выводится в stderr).

Модульные тесты:

```
python -m unittest discover -s tests -t .
```


## Этап 1. Минимальный прототип с конфигурацией

Все настраиваемые параметры задаются в XML-файле:

```xml
<config>
    <package>express</package>                          <!-- имя пакета -->
    <repository>https://registry.npmjs.org</repository> <!-- URL или путь к файлу -->
    <test_mode>false</test_mode>                        <!-- режим тестового репозитория -->
    <version>4.18.2</version>                           <!-- версия пакета -->
    <output_file>output/express.svg</output_file>       <!-- файл изображения графа -->
    <ascii_tree>true</ascii_tree>                       <!-- вывод ASCII-дерева -->
    <max_depth>2</max_depth>                            <!-- максимальная глубина -->
</config>
```

| Параметр | Проверка |
|---|---|
| `package` | не пустое; имя npm (строчные буквы, цифры, `- . _ ~`, область `@scope/`, ≤ 214 символов); в тестовом режиме — большие латинские буквы |
| `repository` | URL `http(s)://…`; в тестовом режиме — существующий файл |
| `test_mode` | `true` / `false` |
| `version` | точная версия SemVer (`4.18.2`, `1.0.0-beta.1`) или `latest` |
| `output_file` | имя файла `.svg`; каталог должен существовать |
| `ascii_tree` | `true` / `false` |
| `max_depth` | целое число ≥ 1 |

Также проверяются: существование файла конфигурации, корректность XML,
корневой элемент `<config>`, неизвестные, повторяющиеся и отсутствующие
параметры. Демонстрация всех ошибок — `scripts/stage1_errors.sh`
(`.bat`), файлы с ошибками лежат в `configs/errors/`.


## Этап 2. Сбор данных

Модуль `src/npm_registry.py`. Метаданные пакета скачиваются запросом
`GET <repository>/<имя>` (для `@scope/name` — `@scope%2fname`) с
заголовком `Accept: application/vnd.npm.install-v1+json` — это
сокращённый формат, который использует сам npm. Из ответа берутся
`dist-tags` и `versions[<версия>].dependencies`.

Учитываются только `dependencies` — то, что устанавливается вместе
с пакетом (`devDependencies` нужны лишь при разработке самого пакета).
Ошибки: пакет не найден (404), нет такой версии, сеть недоступна,
ответ — не JSON.

```
scripts/stage2.sh          # прямые зависимости express, chalk, axios
```


## Этап 3. Основные операции

* Граф строится **обходом в ширину с рекурсией** (`src/graph.py`,
  `build_graph`): функция `bfs(level, depth)` раскрывает весь текущий
  уровень и рекурсивно вызывает себя для следующего уровня.
* `max_depth` — число уровней от корня: при `1` выводятся только прямые
  зависимости; узлы на последнем уровне не раскрываются (помечаются).
* **Циклы.** Каждый узел раскрывается один раз, поэтому обход конечен.
  Циклы находятся отдельно (ребро в узел, лежащий на текущем пути) и
  выводятся как `A -> B -> C -> A`.
* **Версии транзитивных зависимостей.** В `dependencies` указаны
  диапазоны (`^1.2.0`, `~2.0`, `>=1 <3`, `1.x || 2.x`, `1.0 - 2.0`).
  Для их разбора написан модуль `src/semver.py`. Как и npm, программа
  берёт версию с меткой `latest`, если она входит в диапазон, иначе —
  наибольшую подходящую. Узел графа — `имя@версия`.
* **Тестовый режим** (`<test_mode>true</test_mode>`): `repository` —
  путь к файлу, пакеты — большие латинские буквы:

```
# комментарий
A: B C
B: D
C: D
D:
```

Тестовые графы в `data/`: `graph_simple.txt` (ромб), `graph_cycle.txt`
(цикл A→B→C→A), `graph_complex.txt` (циклы B↔D и E→E),
`graph_deep.txt` (цепочка для `max_depth`), `graph_bad.txt` (ошибка).

```
scripts/stage3.sh
```

Пример (`configs/test_cycle.xml`):

```
Граф зависимостей A: узлов 4, рёбер 4
  [0] A -> B
  [1] B -> C
  [2] C -> A, D
  [3] D -> -
Циклические зависимости: 1
  A -> B -> C -> A
```

`configs/test_deep2.xml` (цепочка A→…→F, `max_depth` = 2):

```
Граф зависимостей A: узлов 3, рёбер 2
  [0] A -> B
  [1] B -> C
  [2] C -> - (не раскрыт: max_depth)
```


## Этап 4. Дополнительные операции: порядок загрузки

```
python src/main.py configs/test_complex.xml --load-order
```

Порядок загрузки — обратный топологический: пакет загружается после
всех своих зависимостей (обход в глубину, пакет добавляется в список
после зависимостей). Ребро, замыкающее цикл, при этом пропускается.

| Граф | Порядок загрузки |
|---|---|
| `graph_simple.txt` (ромб) | D, B, C, A |
| `graph_cycle.txt` | D, C, B, A |
| `graph_complex.txt` | G, D, H, E, B, K, J, I, F, C, A |

### Сравнение с npm

Сравнение: `scripts/compare_npm.sh chalk 4.1.2` (нужен Node.js) —
устанавливает пакет во временный каталог и сохраняет `npm ls --all`.
Набор пакетов и версий у программы и npm совпадает, если граф не
обрезан `max_depth`. Расхождения в порядке объясняются так:

* npm не загружает пакеты строго по одному: метаданные и архивы
  скачиваются параллельно, порядок скачивания недетерминирован.
  Зависимости-перед-зависящими соблюдается только при выполнении
  install-скриптов (`preinstall`/`install`/`postinstall`) — это и есть
  порядок, который выводит программа.
* npm сначала строит дерево целиком (`idealTree`), выравнивает
  (hoisting) и дедуплицирует пакеты в `node_modules`; при наличии
  `package-lock.json` версии берутся из него, а не по правилу
  «latest / максимальная подходящая», поэтому версии могут отличаться.
* npm ≥ 7 устанавливает `peerDependencies`, а `optionalDependencies`
  пропускает, если пакет не подходит для платформы (поля `os`, `cpu`).
  Программа учитывает только `dependencies`.
* При цикле npm тоже не может выдержать порядок для всех пакетов цикла;
  программа разрывает цикл на ребре, которое его замыкает.


## Структура проекта

```
src/config.py         чтение и проверка XML-конфигурации
src/npm_registry.py   загрузка метаданных из npm-репозитория
src/semver.py         версии и диапазоны SemVer
src/test_repo.py      тестовый репозиторий из файла
src/graph.py          BFS с рекурсией, циклы, порядок загрузки
src/visualize.py      Graphviz (DOT), SVG, ASCII-дерево
src/main.py           точка входа
configs/              примеры конфигураций (errors/ — с ошибками)
data/                 графы тестового режима
examples/             готовые изображения
scripts/              сценарии демонстрации этапов
tests/                модульные тесты
```
